### Forward contract and proposed layer design

| Stage | Shape | Responsibility |
| --- | --- | --- |
| Input IDs | `[B, T]` | Unpadded integer token IDs with `1 <= T <= context_length`. |
| Token lookup | `[B, T, D]` | Read from the shared learned matrix `[V, D]`. |
| Q, K, V | Each `[B, H, T, d_h]` | Project separately, reshape into heads, and rotate Q and K. |
| Attention output | `[B, H, T, d_h]` → `[B, T, D]` | Use causal SDPA, merge heads, and apply the output projection. |
| SwiGLU | Two `[B, T, F]` projections → `[B, T, D]` | Apply SiLU to the gate, multiply by the up projection, then down-project. |
| Draft logits | `[B, T, V]` | Apply final RMSNorm and project using the same token weight. |

- **RMSNorm.** For each token vector `x`, compute
  `weight * x / sqrt(mean(x²) + eps)` over the last dimension. The
  learned weight is a length-`D` scale vector.
- **RoPE.** Use adjacent-channel pairs in each head. Apply a 2D rotation
  to pair `i` at position `p` with angle
  `p × rope_base^(-2i/d_h)`. Both Q and K use the same frequencies
  with their own positions. The dot product then depends on their
  relative position. Precompute cosine and sine through the context limit
  and keep them as nonpersistent buffers.
- **Causal self-attention.** For the uncached full sequence, Q and K have
  equal length. Use `F.scaled_dot_product_attention` with `is_causal=True`
  and dropout 0.0 so row `i` sees keys through `i`. Recombine heads before the
  `D → D` output projection.
- **Pre-norm and tied output.** Apply each normalization before its
  sublayer and add that sublayer's output to the residual stream. In
  order, use `x = x + attention(attn_norm(x))` and
  `x = x + swiglu(ffn_norm(x))`. Project final normalized states with
  `F.linear(hidden, token_embedding.weight)` so both uses share one
  parameter. The forward returns logits. The initial-loss check computes
  next-token cross-entropy from shifted labels outside the model.
- **Config.** Keep the existing dimension keys and tokenizer ID. Derive
  `head_dim` and validate positive integer dimensions, width divisibility
  by head count, even head width for RoPE, and finite positive RoPE and
  RMSNorm settings and the approved dropout. Report invalid YAML fields,
  input rank, and context length clearly. Verify tokenizer alignment
  separately so toy model tests can use a small vocabulary.

### Proposed cache and forward contract

- `model.new_cache()` returns an empty cache for one batch-one request
  using the model's layer count and context limit. The cache holds one
  K/V pair per layer with shape `[1, H, P, d_h]`, where `P` is the
  retained length shared by every layer. Store rotated keys and unrotated
  values. Keep cache tensors on the device and dtype of the layer's K/V
  projections. The cache is request state and adds zero trainable
  parameters.
- `model.forward_cached(input_ids, cache)` consumes only the new token
  chunk, shaped `[1, T]`, and returns logits shaped `[1, T, V]`.
  With an empty cache this prefills the prompt. With a populated cache it
  supports a single token or a multi-token chunk. Row `i` predicts the next
  token after the input at absolute position `P + i`. Run the cached forward
  without gradient tracking. The ordinary `model(input_ids)` remains the
  differentiable full-sequence reference.
- Take `P` before the layer loop. Give the new Q and K absolute positions
  `P` through `P + T - 1` in every layer. Concatenate new K/V after each
  layer's retained prefix once and reuse those combined tensors for
  attention and the updated cache. Publish the complete set of pairs only
  after a successful forward. Validate the chunk and cache compatibility,
  including batch size, layer layout, device and dtype, before publishing
  any update. Require `T >= 1` and `P + T <= context_length`.
- `cache.crop(n)` retains the first `n` positions on every layer's sequence
  axis and rejects values outside `0 <= n <= P`. Cropping to zero clears the
  cache. The next forward derives its RoPE positions from the reduced
  length. Cached keys keep the rotation they received when first appended.

### Causal masking

| Forward | Allowed keys | SDPA arguments |
| --- | --- | --- |
| Prefill or full sequence, `P = 0` | Query row `i` can attend through key `i`. | `is_causal=True` |
| Cached single token, `P > 0, T = 1` | The sole query can attend to every retained key and its own key. | `is_causal=False` |
| Cached multi-token chunk, `P > 0, T > 1` | Row `i` can attend through key `P + i`. | Boolean mask shaped `[T, P + T]` with `key_index <= P + query_index` and `is_causal=False` |

PyTorch 2.11 uses an upper-left causal bias for rectangular attention.
An SDPA Boolean mask uses `True` for an allowed attention position.
The explicit offset mask gives each query the retained prefix and the
causal part of its own chunk. [PyTorch 2.11 SDPA documentation](https://docs.pytorch.org/docs/2.11/generated/torch.nn.functional.scaled_dot_product_attention.html)

| Check | Acceptance criterion |
| --- | --- |
| Prefill and append | Empty-cache prefill matches full-sequence logits. Assert every layer's K/V shape and retained length after each append. |

| Greedy generation | Starting from the same fixed prefix, select the next token from the last logit row and feed each selected token once. Cached and uncached generation produce identical token IDs at every step. |
| Causal perturbation | Change a token later in a cached multi-token chunk. Earlier chunk logits match within tolerance and at least one logit at or after the changed position differs. |
| Crop and regenerate | Append a suffix, crop to an earlier retained length, and continue with a different suffix. New logits match the fresh uncached path and greedy continuations match exactly. Verify the retained K/V slices and repeat prefill after `crop(0)`. |

### Corpus and training recipe

- Seed a dedicated CPU generator with `20261119`. Permute 128 synthetic
  token IDs (`256` through `383`) into a cycle, then draw 100 distinct
  starting offsets from a seeded permutation of that cycle. Repeat the
  cycle from each selected offset to produce 256 tokens per sequence.
  Keep the generated order fixed across epochs. The varied targets have
  a consistent successor for each token, making the repeated corpus a
  controlled memorization task. The fixture needs no tokenizer, model
  downloads, or benchmark data.
- Seed Python, NumPy, and torch with `20261118` before model construction.
  Enable deterministic torch algorithms and use four CPU intra-op threads.
  Save and restore the process RNG and thread/determinism settings around
  tests. Keep the full vocabulary and tied head from `configs/draft_a.yaml`.
- Feed one sequence per update. Use `tokens[:, :-1]` as model input and
  `tokens[:, 1:]` as labels, with 255 targets and 32,000 logits per target.
  Compute mean cross-entropy over those targets on the ordinary
  differentiable `DraftModel.forward` path. Use `zero_grad(set_to_none=True)`,
  forward, backward, gradient clipping at norm `1.0` with nonfinite errors
  enabled, and `optimizer.step()`. Fail on nonfinite loss or gradient norm.
- Proposed optimizer settings are AdamW, constant `lr=1e-3`,
  `betas=(0.9, 0.95)`, `eps=1e-8`, `weight_decay=0.0`, and
  `foreach=False`. Use a budget of three passes through the corpus, at
  most 300 optimizer steps. FP32 with constant LR leaves the GradScaler
  and scheduler states explicitly absent.

### Checkpoint handling

- Save after the initial evaluation, every 25 completed updates, and at
  each epoch evaluation. Atomically replace one checkpoint via a temporary
  sibling file. Store model and optimizer state, scaler and scheduler
  fields (`None`), Python/NumPy/torch CPU RNG state, the data generator
  state, the global step and next sequence index, and the loss history.
  Bind the checkpoint to the resolved config and the generated token
  corpus with SHA-256 fingerprints. Keep the checkpoint outside the repo.
- Resume only when explicitly requested and a compatible checkpoint
  exists. Rebuild the same corpus and validate fingerprints and saved
  cursor. Restore the model and optimizer, then restore RNG state before
  the next update. Run the corpus-wide evaluation after the final update
  of each epoch and before publishing its checkpoint so a resume preserves
  the same stopping decision. Refuse an existing checkpoint for a fresh
  run to avoid stale evidence.
