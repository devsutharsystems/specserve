## Day 2 — Theory, frozen benchmark, and baselines

### Goal and success criteria

Learn the inference arithmetic and speculative-decoding theory, then build and
freeze a reproducible 100-prompt benchmark and baseline implementations without
using benchmark prompts for training, distillation, or tuning. Day 2 is split
into two independently approved gates:

- **Day 2a (local):** build, validate, freeze, and commit
  `bench/prompts.jsonl`.
- **Day 2b (local/Kaggle):** build baseline code and tests, run Kaggle
  baselines, and return measured results.

Success means:

- Day 2a produces exactly 25 prompts in each of the four categories and 100
  prompts total, selected with a fixed seed, then freezes and commits
  `bench/prompts.jsonl`.
- JSONL stores raw prompts with the schema
  `id`, `category`, `source`, `source_id`, `prompt`, `max_new_tokens` (128),
  and `prompt_tokens`.
- All four categories come from UltraChat `test_sft` first-user turns, with
  `source` set to `HuggingFaceH4/ultrachat_200k:test_sft` and `source_id` set
  to the source `prompt_id`.
- Category filters are fixed before candidate counting, assign each selected
  prompt to exactly one category using the stated priority order, and cap
  `prompt_tokens` at 896.
- All methods use one shared tokenizer-template function built from the
  tokenizer's own template, with the template verified against
  `tokenizer_config.json`. The length check uses templated token IDs including
  BOS and the generation prompt, and verifies `prompt_tokens + 128 <= 1024`.
- Day 2b uses `specserve/decode/greedy.py` for the HF TinyLlama KV-cache
  greedy loop and `specserve/decode/prompt_lookup.py` for model-free n-gram
  copy drafting, with one shared loop and timing harness.
- Day 2b returns baseline CSVs and environment metadata in
  `experiments/baseline/*.csv` and `experiments/env.txt`.

### Measurement specification

- The first generated token comes from the prefill pass. Therefore
  `prefill_s` includes that token and
  `decode_tok_per_s = (tokens_generated - 1) / decode_s` for every method.
  Carry this same convention into the speculative engine.
- Timers start after tokenization, with input IDs already on the device, and
  end after the final `torch.cuda.synchronize()`. `tokens_generated` includes
  EOS when EOS is emitted, and this rule is identical for every method; stop
  at EOS or `max_new_tokens`.
- **End-to-end latency:** `total_s`, measured from the timer start through the
  final synchronization, including prefill, decode, and required loop
  overhead. Record `prefill_s` and `decode_s` separately.
- The baseline CSV must include at least
  `method`, `prompt_id`, `repeat`, `tokens_generated`, `prefill_s`,
  `decode_s`, `total_s`, `decode_tok_per_s`, `dtype`, `seed`, `git_commit`,
  and `model_revision`; `model_revision` is the pinned TinyLlama revision
  recorded in row 8 of `docs/project_spec.md`. It must also include the
  configured batch size, max new tokens, EOS/stopped status, and any
  acceptance/log fields needed to identify the method's iteration behavior.
- Warmups must run before measured repeats; the warmup count is a proposed
  reference-implementation setting, marked `verify`, and fixed before any
  benchmark run.
- Proposed prompt-lookup settings must be taken from the reference
  implementation: n-gram size (reason: define the copied-context match),
  draft length (reason: bound each copy proposal), and warmup count (reason:
  remove one-time setup from measurements). Mark each `verify`, fix them
  before any run, and never tune them on the frozen benchmark.
- Use batch size 1, `torch.cuda.synchronize()` around timed regions, three
  repeats, and report the median and spread.
